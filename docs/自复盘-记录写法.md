## 这是什么

每个交易日盘后，不看课件，只凭独立数据，写出当天「变了什么、读哪个锚、影响哪条主线、本地跟没跟、什么情况下撤」。产出是一份 `records.json`，落 `data/self_recap/<交易日>/`。

方法是两份文件：

- 分析步骤：`/Users/lunarabbit/Documents/Codex/Project Mirror/烛照九阴日报/skills/anchor-follow/SKILL.md`（V.V. 的锚跟随技能，六步）。
- 每类锚怎么读：`Projects/Financial/Event-Attribution-Ledger/研究材料/锚定-跟随流派/锚的大类逻辑卡.md`（八张卡加七条通则）。

## 三步

```bash
cd ~/Documents/Claude/Projects/Financial/烛照九阴
python3 tools/self_recap_inputs.py                      # ① 出输入包 data/self_recap/<交易日>/inputs.json
```

输入包里有两块：`local` 是各主线对沪深 300 的 5 日、20 日超额和对应美股锚的 20 日超额；`external` 是 V.V. 工具给的美股锚、外围、主线 ETF 最新行和资讯原始标题与网址。先读 `local_gaps` 与 `external.gaps`，缺的就是缺的。

`local` 的口径：

- 窗口按交易日历取（`local.windows` 写明起止日）。行情缺一天，对应读数为空并记缺口，窗口不会往前挪。
- 主线含多只 ETF 时取等权均值，`pct_chg`、`e5`、`e20` 同一口径；`pct_chg_members` 列出每只的当日涨跌。任何一只缺数，这一项为空并记缺口，不拿剩下的成员顶替。
- 美股锚带 `window_end`（20 日窗口的最后一天）。它与 A 股的截止日不同，基准也不同（标普 500 与沪深 300）。

## 先后次序（并行期必须守）

**先写完自复盘记录并校验通过，再去读当天的课件和课件入库内容。** 次序反了，对照就不是盲的，这一天的对照结果只能验证流程，不能当证据。不得已反了序的，在 `records.json` 里写 `"blind": false` 并说明。

## 怎么挑对象

按输入包里的数值挑，不凭印象：

1. 当日涨跌幅和 20 日超额在两端的主线。
2. 锚与本地方向不一致的主线：锚强而本地不跟，或本地强而锚弱。
3. 资讯里有当天新出现、且能对上某条主线的原始报道。
4. 宏观读数（收益率、汇率、原油、海外指数）当天有明显变化时，出一条不挂主线的环境记录。

没有外部锚的主线，只在 `local_only` 里记本地读数，不硬配一个锚。当天确实没有变化，`records` 留空并写 `no_change_note`。

## 记录格式

文件顶层：

| 字段 | 含义 |
|---|---|
| `schema_version` | 固定为 2 |
| `trade_date` | A 股交易日，`YYYYMMDD` |
| `session` | 固定为 `盘后` |
| `observed_at` | 写这份记录的时刻，带时区，如 `2026-11-17T08:00:00+00:00`；不得早于交易日 |
| `inputs_sha256` | 同目录 `inputs.json` 的 SHA-256。校验器会核对校验值，并核对输入包的交易日与本记录一致 |
| `blind` | 必填，`true` 或 `false`：是否在看课件之前写成。`false` 时必须写 `blind_note` 说明原因 |
| `records` | 记录列表 |
| `carried_over` | 上一期的记录里，本期没有接着写的那些：每项含 `ref`（上一期记录的 id）、`outcome`（`已结` 或 `搁置`）、`note`（为什么）。上一期每条都接上了就不用写 |
| `local_only` | 可选。只有本地读数、没有外部锚的主线 |
| `no_change_note` | `records` 为空时必填 |

每条记录：

| 字段 | 含义 | 约束 |
|---|---|---|
| `id` | 记录编号 | 当日内不重复 |
| `theme` | 对应的主线名 | 必须是 `scripts/fetch_theme_etf.py` 里 `THEME_ETF` 的键；没有对应主线写 `null` |
| `object` | 说的是哪个对象 | |
| `main_issue` | 今天支配它的主要矛盾 | |
| `anchor` | `name`、`card`、`role` | `card` 为卡一至卡七；`role` 是锚相对对象的关系：同向印证、温度计、反向或替代、事件或预期。本地跟不跟写在 `local_confirmation`，不是锚的角色 |
| `evidence` | 证据列表，每条含 `kind`、`ref`、`asof` | 见下面「证据怎么写」 |
| `transmission` | 传导链与商业暴露：`chain`、`exposure`、`status` | `chain` 写锚的变化怎样一步步传到对象；`exposure` 写对象在这条链上的客户、订单或收入占比。`status` 为已核、部分已核、未核；温度计与对象没有直接商业关系，写不适用。没核到就写未核，不要编。未核时方向不得写可加 |
| `change` | `baseline` 与 `delta` | 没有可追溯的此前预期，`baseline` 写「基线未核」 |
| `direction` | 方向 | 只能是可加、宜减、不动、观察。本地未确认时不得写可加 |
| `stage` | 完备度 | `观察`：只记读数与假设，方向只能是观察或不动。`条件草案`：给了方向，同时在 `stage_basis` 里写明方向依赖哪些可观察的条件、还差什么。给了可加或宜减就必须是条件草案 |
| `local_confirmation` | `status` 与 `basis` | `status` 为已确认、未确认、待确认 |
| `priced_in` | 哪一段已经反映、哪一段还没有 | 拿不准写「待核」并说明缺什么 |
| `invalidation` | 什么情况下撤 | 必填 |
| `next_check` | 下一个验证点 | |
| `prior` | 与上一期的承接：`ref`、`carry` | `ref` 写上一期对应记录的 id，没有写 `null`。`carry` 写上一期留下的验证点这一期看到了什么；首次出现就写明 |

## 上一期的事要有去向

写之前先读上一期的 `records.json`（只读，不改）。上一期的每条记录，本期要么有一条记录用 `prior.ref` 接上，写明它留下的验证点现在怎样了；要么写进顶层的 `carried_over`，说明是 `已结`（条件已失效或已兑现，不再跟）还是 `搁置`（当日没有新读数，下一期再看）。校验器会逐条核对，漏一条就不过。只接上一期，不往更早跳。

上一期是旧格式也一样接，只用它的 id。原判断不事后改写：上一期说错了，就在 `carry` 里照实写它错在哪。

## 证据怎么写

| `kind` | `ref` 的写法 | 另需 |
|---|---|---|
| `market_data` | `market_data.db:<行情表>:<代码>:<日期>`。表限于行情表（指数、ETF、美股锚、外围、个股、成交额、利率等），涨停名单不在内 | |
| `inputs` | `inputs.json:<块内路径>`，如 `inputs.json:local.themes[机器人]` | |
| `url` | 带文章路径的完整网址，照输入包里的原样抄，不截短；查询串可以去掉 | `body_read`：`已读正文` 或 `仅标题`。`first_public_at`：这件事首次公开的时刻，带时区；不知道写 `未核` |
| `eal`、`yuantu` | 能找回原件的路径或编号 | |

- `asof` 是这条证据的日期或时刻：`YYYYMMDD`、`YYYY-MM-DD`，或带时区的时刻。它不得晚于 `observed_at`。
- 资讯聚合站给的时间是它列出这条消息的时间，不是事件首次公开的时刻。两者分开写：前者进 `asof`，后者进 `first_public_at`。
- 数值写有限数。取不到就不写这条证据，在正文里说缺什么。
- 不引用复盘库（`recap.db`）里的任何表，不引用课件与课件派生表。

## 证据够不够，校验器不管

校验通过只说明格式与来源合规。下面这些要写的人自己守，审核的人会读：

- 只读到标题、或首次公开时刻未核的消息，只能当候选解释。它不能单独撑起主矛盾，也不能单独撑起方向；方向要有价格读数或已读正文的材料支持。
- 说「已经计价」，要拿同一个截止日的读数比，并写明各自对的是什么基准。本地与美股锚的 20 日超额截止日不同、基准不同，数值接近不说明同一件事已被计价。拿不准就写「待核」。
- 不同窗口的读数不写成同一时点的比较。`external` 里晚于 A 股收盘的读数，只能说「本地还没有机会反映」。
- 先后不是因果。价格背离只说明方向不一致，不足以排除别的原因。
- 「没有新消息」写成「本次检索没有找到已核的新消息」。
- 多只标的一起说时，分别写各自的读数。

## 不许出现的

整份记录的任何文字里都不得出现：均线闸门、几成仓这类成数与仓位百分比、成交额的绝对阈值、固定天数的止损、外汇掉期、涨停与连板相关的依据、课件的周期判定。证据的备注、`local_only`、`no_change_note` 也算在内。任何位置都不得指向课件、课件派生表、课件文件或复盘库（`blind_note` 里说明是否看过课件除外）。

证据里可以如实记成交额的数字与前后比较；它只是事实，不当阈值用。同样的话写进判断文字就算阈值。

校验器按字面拦常见写法（含小写、全角、换个单位），拦不住所有改写。换一种说法绕过去不算合规。

## 时钟

- 美股锚：`local` 块只取严格早于 A 股交易日的美国日期。A 股当日收盘时，美股同日还没收盘。
- `external` 块是「现在」的最新行，可能已经包含 A 股收盘之后的美股时段。用它时在 `priced_in` 里写清：这一段本地还没有反映。
- 期货、收益率这类带「取数时点快照」注记的读数，不当收盘价用。

## 对照

```bash
python3 tools/self_recap_compare.py --date <交易日>
```

写 `data/self_recap/compare.csv`，一个交易日一行：课件当日点到的主线、自复盘覆盖的主线、各自独有的主线。「方向相反」一栏脚本不算，由审核的人读两边文字后填 `opposite` 与 `opposite_note`。

人工填的结论跟着两侧内容的版本走：每行记着自复盘记录与课件当日信号各自的校验值（`self_sha256`、`kejian_sha256`）。重跑时有一侧变过，已填的内容照留，`opposite_review` 标「待复核」；审核的人重读后改好结论，再把这一栏清空。`blind` 一栏写当日是否盲写，非盲写的那一行只验证流程，`note` 里会注明。

## 边界

- 输入包的 `external` 块不支持回放历史日期，它永远是运行时刻的最新行。补做过去某天的记录时，只有 `local` 块是当日口径。
- 本文与三个脚本只保证记录能独立产出、来源可查、写法完整，不保证判断有预测价值。
- 这是轻量的研究记录，不是锚跟随技能要求的完整输出。技能里完备度的第三档「具备执行条件」要有入场价格、仓位依据与账户约束，Doctor 裁定自复盘只提示方向，这里没有那一档，也没有这些字段。
- `schema_version` 为 1 的旧记录（2026-11-17 复核之前写的）不按本版校验，也不能重跑对照。
